## Benchmark protocol (Phases 1–4)

Every headline result comes from **≥3 independent training seeds** (5+ for the capstone), reported as mean ± std across seeds — deep RL is brittle with respect to random seed (per Spinning Up), so single-run numbers don't count. The per-run eval protocol (fixed eval seeds, deterministic policy, N episodes) is unchanged.

Execution: any run longer than ~5 minutes — i.e. every real training run (a 5M-step MinAtar run is ~55 min) — is launched by the maintainer in their own terminal; Claude hands over the exact command (env vars included) and picks up from the logged output and checkpoints. Learned on a prior project: training launched through Claude Code tooling runs ~10x slower. Short smokes and tests stay in-session.

## Phase 1 — DQN (discrete track)

Replay buffer, target network, ε-greedy exploration; Double DQN / Dueling / n-step returns as config toggles. Benchmark on CartPole/LunarLander for sanity, then MinAtar (install `minatar` at phase start). Headline metric vs a published baseline.

**Known, chosen difference from common DQN references (audited 2026-07-25 against the PyTorch DQN tutorial): our DQN applies no gradient clipping.** PPO clips grad-norm at 0.5; DQN clips nothing, where that tutorial uses `clip_grad_value_(params, 100)`. Largely self-mitigating — the Huber loss already clamps ∂L/∂Q to ±1 per sample, which is the dominant gradient-blowup path in DQN and much of why Huber is the standard choice there; a value clip at 100 is a loose outer safety net on top. **Deliberately not added**: no instability appeared across 63 five-million-step runs, and changing it now would break comparability with the entire Phase 1 campaign for no measured benefit. Other differences from that tutorial are all MinAtar-paper fidelity rather than oversight — hard target sync every 1000 gradient steps (not Polyak τ=0.005), linear ε decay (not exponential), Adam/centered-RMSprop (not AdamW+amsgrad), batch 32 / buffer 100k / lr 2.5e-4 — and the optimizer question was settled empirically in Phase 1 rather than by default-copying. Terminal handling is equivalent to the reference (`(1 - terminated)` masking vs their `next_state = None`), and both bootstrap correctly through truncation.

**On-ramp (first step of the phase): linear Q-learning on CartPole.** The DQN skeleton with a zero-hidden-layer network (`nn.Linear(4, 2)`) — a linear model borrowing all the same infra. Isolates the one conceptual leap from Phase 0 (shared weights generalize across states; the same TD error now takes a gradient step instead of a table-cell nudge) and meets the deadly triad — function approximation + bootstrapping + off-policy, where tabular convergence guarantees evaporate — *before* the target network and replay buffer arrive as its stabilizers. Then add the hidden layer and it's DQN. Optional half-hour calibration first: random search over linear policies solves CartPole outright — a reminder that "solves CartPole" is a low bar, which is why the headline benchmark is MinAtar.

**Visuals (starts here, grows with the project):** better visuals serve three purposes — learning (seeing what a policy actually does), validation (a rendered rollout catches bugs metrics hide), and eventual sharing/posts (this repo is a portfolio piece). First deliverable, once DQN produces a policy worth showing: a `--record` path or `scripts/record.py` using `render_mode="rgb_array"` to save rollouts as annotated GIFs/videos (episode/step/return stamped on frames — cheap once frames are in hand) for the README and posts. Explicitly rejected: HUD overlays in the live `render_mode="human"` window (gymnasium exposes no API for it; the pygame workarounds are fragile) — `watch.py`'s terminal narration covers live viewing.

**Discrete PPO audited against the TorchRL PPO tutorial (official PyTorch docs), 2026-07-25 — three divergences, all on the canonical side; no changes made.** (1) *Advantage recomputation*: the tutorial recomputes GAE inside the epoch loop ("its value depends on the value network which is updated in the inner loop"); we compute it once per rollout. Ours is correct for PPO — the objective is defined over `A^{π_old}`, the importance ratio corrects for policy drift and not critic drift, so refreshing V mid-epochs does not improve the estimate of `A^{π_old}`, it only makes the target move during optimization; baselines/ppo2, CleanRL and SB3 all compute once. Note what we *do* recompute is a different thing and stays: `values`/`old_logp` are recomputed once **at update start** rather than stored during collection (exact — the policy hasn't changed since it acted). (2) *Critic loss*: we use MSE, the tutorial defaults to `smooth_l1`; canonical PPO is MSE. The asymmetry with our DQN (Huber) is deliberate — DQN's TD targets are genuinely outlier-prone, PPO's are GAE returns. (3) *Advantage normalization*: ours is per-minibatch (CleanRL/SB3), the tutorial's `average_gae=True` normalizes the whole batch.

**Continuous track — pre-spec decisions (drafted 2026-07-25; resolved into the chunk-5 spec below by its three-lens review, 2026-07-26).** The TorchRL tutorial is a valuable reference precisely because it takes the *non*-canonical side on three of four forks, which makes the forks visible. Each of these is cheap to decide now and expensive to discover after a benchmark campaign — the chunk-4 lesson:

| Decision | TorchRL tutorial | Canonical PPO (CleanRL `ppo_continuous_action`, SB3, 37-details) | Lean |
|---|---|---|---|
| Action distribution | `TanhNormal`, squashed to the action spec | unbounded `Normal`, action clipped to bounds, log-prob of the **unclipped** action | canonical |
| Scale parameterization | state-dependent head + softplus | **state-independent free `log_std` parameter** | canonical |
| Observation normalization | fixed stats from 1000 random steps | **running** normalizer updated throughout training | canonical |
| Reward/return normalization | none | running return normalization (Engstrom et al. found it significant) | canonical |

- The **`log_std` fork matters most**: a state-dependent scale head is what *SAC* does (and there it needs the tanh log-det-Jacobian correction). If PPO also used one, the Phase 3 PPO-vs-SAC comparison would differ in more than the intended way — the same "hold everything fixed but the algorithm" discipline that made the discrete headline clean.
- **Fixed observation stats are a locomotion trap**: a random policy on HalfCheetah visits a completely different state distribution than a trained one, so stats computed from random rollouts go stale exactly as the agent improves.
- Both normalizers are **new harness surface**, not agent-internal: they are env wrappers with state that must be checkpointed and restored, or eval and any resumed run silently use the wrong statistics.
- **Entropy coefficient wants revisiting, not porting**: CleanRL runs `ent_coef=0.0` on MuJoCo against our 0.01 for discrete (the tutorial uses 1e-4). Exploration comes from the learned scale parameter, so the bonus carries much less weight.
- Sanity gate before any MuJoCo campaign: a cheap continuous env (Pendulum, or HalfCheetah at short budget) green first — the chunk-3 CartPole role for this track.

## Phase 3 — SAC (continuous track) — COMPLETE (2026-07-26)

Twin Q critics, reparameterized squashed-Gaussian actor with the tanh log-det-Jacobian correction, auto-tuned entropy temperature, soft target updates. Benchmarked against the Phase 2 PPO runs on HalfCheetah-v5 / Hopper-v5 / Walker2d-v5, 1M steps × 3 seeds (0/100/200).

**Prerequisite the repo does not yet have: a shared Polyak soft-update helper** (`rl/common/`, `theta_target <- tau * theta + (1 - tau) * theta_target`, tau ~5e-3). Nothing in `rl/` implements it today — DQN hard-syncs its target net by `load_state_dict` every N gradient steps, which is the right choice there and paper-faithful, but soft updates are *core* to SAC rather than optional, and its twin critics both need them every step. It belongs in `rl/common/` as a small tested utility rather than reinvented inside the SAC agent, since that also keeps a soft-update DQN available as a cheap future ablation against the hard-sync baseline. (Surfaced 2026-07-25 while auditing our DQN against the PyTorch DQN tutorial, which uses Polyak at tau=0.005 where we hard-sync — see the Phase 1 note.)

**Phase 3 spec (locked 2026-07-26 after its three-lens review: 19 keep / 24 amend / 2 reject).** Both rejects were errors in the draft's *justifications*, not its choices — every design decision survived. Recipe taken WHOLE: CleanRL `sac_continuous_action.py` (the chunk-4 lesson; mixing coherent recipes is how MinAtar got mis-tuned).

**Three forks the maintainer settled before the review, and must not be silently re-litigated:**

- **M1 — SAC runs on RAW envs**, no obs/reward normalization, where our PPO's MuJoCo configs run with both on. Every SAC reference (paper, SpinningUp, CleanRL, SB3 default, Tianshou) runs raw, so published SAC numbers stay valid anchors — and for a from-scratch implementation, off-recipe makes "a bug" and "a config difference" indistinguishable. Two independent published benchmark suites already ship *exactly* this asymmetry: Tianshou's `mujoco_ppo.py` sets `obs_norm=True`/`return_scaling=True` while `mujoco_sac.py` sets `obs_norm=False`; SB3's rl-zoo MuJoCo SAC entries carry no `normalize` key. **The confound is closed by measurement, not prose: a PPO-raw control campaign** (the shipped PPO configs with both flags false, 9 runs, ~5 min) makes the headline SAC-raw vs PPO-raw on an identical stack, with PPO-normalized reported alongside to price the env stack. The correctness case is also published — SimBa (arXiv:2410.09754 §7.1) measures env-wrapper running normalization under a replay buffer and finds it "introduces inconsistencies in off-policy settings by normalizing samples with different statistics based on their collection time"; and reward scale is not neutral for SAC specifically, because v2's auto-tuned α absorbs reward scale only against a target entropy **fixed in nats** (`H_target = −act_dim`), so a drifting reward scale makes α chase (Haarnoja 2018a: "reward scale ... the only hyperparameter that requires tuning"; 2018b §5: "the scaling factor has to be compensated by the choice of a suitable temperature").
- **M2 — Tier-1 nets 256×256 ReLU** (the paper's own Table-1 values), plus an **architecture ablation of PPO's architecture WHOLE — 64×64 Tanh — on HalfCheetah at 3 seeds**. Three seeds, not one: single-seed MuJoCo results are noise and ≥3 seeds is the repo floor everywhere else; runs are single-threaded, so 3 concurrent ≈ 1 in wall-clock. Deliberately not decomposed into a width × activation 2×2 — the question is "would matching PPO's architecture have changed the conclusion", not "what does width contribute vs activation". **Limitation stated in the write-up: one env, so the finding is "on HalfCheetah, architecture accounts for X of the gap", never a general claim.** Pre-registered against a bug hunt: the closest published predictor (Henderson et al. 2017, HalfCheetah/DDPG) has 64×64 **tanh** at 5325 ± 281 *beating* 64×64 ReLU at 4198 ± 606 and within ~5% of 400×300 ReLU, while SimBa finds actor scaling "tends to reduce performance" — **a small gap is the published-consistent outcome, not a misconfigured ablation.**
- **M3 — validate SAC against published SAC benchmarks BEFORE the PPO comparison is treated as meaningful.** That is the correctness check the take-the-recipe-whole discipline exists to buy.

Don't write the claim down.
- *Actor.* `mlp(obs_dim, hidden_sizes, 2*act_dim, activation)` chunked into `(mean, log_std)`. The single-head-chunk equivalence was challenged and **verified rigorously**: identical param count (3084 vs 3084), identical `fan_in` (`_calculate_fan_in_and_fan_out` reads `size(1)`, so it is independent of `out_features`), identical per-element init bound (0.0625), KS tests on weights and biases agree (p = 0.72 / 0.47), gradients through `chunk` match separate heads exactly. Two qualifications: the equivalence is *distributional*, not per-seed (RNG draw order differs, so this is not bit-reproducible against CleanRL), and it holds **only because `mlp()` applies no activation after the output layer** — if that ever changes, `chunk` silently becomes two heads sharing a nonlinearity. `log_std` uses CleanRL's tanh-rescale `LOG_STD_MIN + 0.5*(LOG_STD_MAX - LOG_STD_MIN)*(tanh(log_std) + 1)` with **(−5, 2)**, verified verbatim; SpinningUp *and* SB3 both hard-`clamp` at (−20, 2), so CleanRL is the outlier in both form and floor, and our gradient-flow rationale is sound reasoning but unsourced — say so. **No orthogonal init** (verified absent in CleanRL, SpinningUp and SB3 SAC; SB3 applies it only in the on-policy `ActorCriticPolicy`) — a stated recipe asymmetry with our PPO, not an oversight. `activation` is a config string (`relu`|`tanh`) mapped through a two-entry dict, existing solely for M2's ablation arm.

Stable form is a **deliberate divergence from CleanRL's `log(scale·(1−y²) + 1e-6)`**, and the review found a much stronger justification than the draft's: the binding error is the **epsilon, not float32** — it distorts from |u| ≳ 7.6 in float64 too, and it drives the correction's **gradient to exactly zero in saturation** (measured `d/du`: true 2·tanh(u) → 2.0; CleanRL's form → 0.646 at u=8, **0.0** at u=9), i.e. the entropy pressure that stops the policy going deterministic switches off precisely when it is needed. Value cap `−log(1e-6) = 13.8155`/dim confirmed; float32 `1−tanh²` hits exactly 0.0 at **|u| ≥ 8.664** (draft said ">~9"), with only ~12 valid bits left by u=7. Cost recorded: the M3 anchors were produced *with* the epsilon form, so ours is no longer a bit-identical recipe. **Correction to the draft's evidence:** SB3 does **not** include the `−Σ log s` scale term (it rescales outside, in a normalized [-1,1] action space, exactly like SpinningUp), and neither does the paper (Appendix C Eq. 26). Pathfinder should log `max|mu|` to settle whether a converged actor actually reaches the saturated regime — currently asserted, not evidenced.
- *Update (per env step, CleanRL's structure).* Critic: `y = r + γ(1−terminated)·(min(Q̄1,Q̄2) − α·logπ')`, loss `mse(Q1,y) + mse(Q2,y)`. **Every Q output takes `.squeeze(-1)` and the spec must assert `y.shape == (B,)`** — the review's sharpest catch: without it `(B,1)` broadcasts against `(B,)` into a `(B,B)` target, `F.mse_loss` accepts it with only a `UserWarning`, every critic output is regressed to the **batch mean** (gradient correlation −0.82 with the correct one), and the *actor* loss is accidentally exact under the same broadcast (mean of an outer difference = difference of means) so the policy still moves and nothing looks wrong. Proven end-to-end on Pendulum, 25k steps: **−97.6 correct vs −1720.2 broadcast**, i.e. it fails §gate. A `B=1` unit test passes it. Actor+α delayed TD3-style: `if grad_steps % policy_frequency == 0: for _ in range(policy_frequency)`, **reusing the same minibatch** (verified in source; **not** the paper's scheme — Haarnoja 2018b Algorithm 1 does one actor step per env step on a fresh minibatch, and CleanRL's is an unablated TD3/Yarats import that matches the paper's *count* but batches two consecutive steps on one correlated batch). Latent, not campaign-affecting: `train()` never calls `load_state_dict`, and the three restore scripts only read `act(deterministic=True)`.

## Phase 4 — self-play on-ramp: Connect 4 (added 2026-07-25; spec LOCKED 2026-07-26 after three-lens review)

Goal: build and validate the self-play machinery in isolation, on an environment where a run takes minutes and a ground-truth oracle exists, before the Pokémon domain adds partial observability, stochasticity, long horizons and an external Node server on top of it. Same on-ramp discipline as linear-Q before DQN and REINFORCE before PPO: meet one new mechanism at a time. Self-play is the single genuinely new *mechanism* in the capstone; everything else there is domain.

**Hard constraint — PPO only, no MCTS.** The literature's default for Connect 4 is AlphaZero, and following it would build MCTS, search-derived policy targets and Dirichlet root noise, **none of which transfers**: tree search needs a forward model, and Showdown gives us none (Huang & Lee chose policy optimization for exactly this reason — see Phase 5). **A mediocre Connect 4 agent is a success.** The deliverable is the self-play loop and the Elo harness, not playing strength — written down because otherwise a weak agent reads as a bug and we repeat the chunk-4 afternoon spent proving a mis-tuned lr wasn't one.

**What is structurally different about this phase: there is no published anchor.** Phases 1–3 each graded against published numbers (MinAtar paper; gymnax/CleanRL; Haarnoja/SpinningUp/Tianshou/SB3), and that anchor is what let a bug be told apart from a hyperparameter. No PPO-self-play-on-Connect-4 result exists, and building one is forbidden by the hard constraint. Two consequences drive the whole design: the three-lens review is the only external correctness check available, and **correctness has to come from exact oracles instead of curves** — `open_spiel`'s `connect_four` as a differential oracle for the env, and a negamax solver validated against Pascal Pons' 6000 labelled positions as game-theoretic ground truth. **This overrides the original "No solver build required" line**: Pons' labels give the value of a *position*, and a move is optimal only if its *child's* value is −v(p), so blunder rate and optimal-move agreement are not computable from labels alone. An exact oracle is a stronger check than a published curve.

**Review outcome (2026-07-26): 6 reject / 5 implementation blockers / ~30 amend.** Lenses: published-evidence (re-scoped to general self-play practice + the competitive-Pokémon literature, since no Connect 4 recipe exists), reference-implementation, and adversarial-with-executable-probes. Four adversarial claims were re-derived independently before acceptance; two came out worse than reported, one better. Everything below is post-review.

**Dependencies.** `open_spiel==2.0.1` as a **dev-only test oracle** (`cp313 macosx_11_0_arm64` wheel exists; adds only `attrs` + `ml-collections` on top of what the env already has; never `open_spiel[full]`). **`pettingzoo` is not used** — it would cost `chess`, `rlcard`, `pygame-ce` and `shimmy[openspiel]`, which pulls open_spiel anyway. The Connect 4 env itself is hand-written NumPy — which is also the ecosystem norm, not merely dependency avoidance: PettingZoo ships no official fixed-opponent→gymnasium wrapper and their own SB3 Connect Four tutorial hand-rolls one. See CLAUDE.md's carve-out on the no-RL-libraries rule.

**Pre-registered expectations** (written before running, so a gap is not mistaken for a bug):

- **~50% is the EQUILIBRIUM of self-play, not a failure.** With a randomized first player, a policy playing a frozen copy of itself scores ~0 net. Every "is it learning?" question is answered against the **fixed external anchors**, never against the pool — which is why `eval_opponent` can never resolve to a pool member. Published support: Metamon (RLJ 2025, arXiv:2504.04395 §5.3) let SynRL-V1 battle recent checkpoints of itself, got a model "significantly better against itself" that gave "inconsistent improvement against real players" — "battle replays make it clear that the model believes it is playing SynRL-V1" — in Gen 1 OU, the capstone's exact setting.
- **Connect 4 is a first-player win under perfect play**, so win rate against a perfect player is degenerate (0% as P2 forever regardless of skill). Absolute strength comes from the position benchmark, never from a match against the solver.
- **Forgetting may or may not appear, and the literature genuinely splits.** OpenAI Five scopes strategy collapse to "games with simultaneous-turns and/or imperfect information" (arXiv:1912.06680 App. N) — Connect 4 is neither — and Generals.io (arXiv:2606.23348) ablates population-based self-play out entirely at superhuman level. Against that: Czarnecki et al. (NeurIPS 2020) measure Connect Four's empirical game geometry and place it in the spinning-top class, where **the cyclic dimension is widest at intermediate transitive strength** — exactly the band a pre-registered "mediocre agent" occupies; and Tesauro (CACM 1995) reports self-play pathologies specifically in **deterministic** games (checkers, Go), escaped in backgammon only because dice supply free exploration. Connect 4 is deterministic; our randomized first player, sampled opponent moves and entropy bonus are the substitute noise source Tesauro prescribes, so **a null result is a claim about those mitigations as much as about the game's transitivity.** The old "PLAN.md records that Connect 4 is near-transitive" claim is retired — it was never sourced and the one paper that measured it disagrees. Whatever Phase 4 finds does **not** transfer to Phase 5 by default: Gen 1 Showdown is simultaneous-move *and* imperfect-information, i.e. exactly the class OpenAI Five carves out.
- **PPO's hyperparameters do not port.** ~10.6 learner steps per episode (mean game 21.25 plies, measured over 20k random games) against MinAtar's thousands, and a terminal-only ±1 reward.
- Strength: beats `random` ≫90%, beats `heuristic`, roughly competitive with `alphabeta2`, loses to `alphabeta4`. **No claim about beating alpha-beta at any depth.**

**The env (`rl/envs/connect4.py`) — the highest-value artifact.** `Connect4Board` (pure NumPy, oracle- and solver-testable without gymnasium) plus `Connect4Env`, a learner-centric single-agent view of a two-player game with the opponent living inside. Board `int8 (6,7)`, canonical (`+1` = player to move), `drop()` negates after each move; row 0 = **bottom** (stated because an inverted convention makes every diagonal test pass while the real diagonals are wrong). Obs `Box(0, 1, (2,6,7), dtype=bool)` — MinAtar's own convention — which auto-selects `ConvQNet` for both PPO heads by the existing no-config-key rule (probe-verified: 83,816 params). `Discrete(7)`, native `info["action_mask"]`, and `info["outcome"] ∈ {-1,0,+1}` at terminal. **No turn-indicator plane** — first-player identity is recoverable from the plane sums (verified at every step of 30 full games), and this is the reference norm: alpha-zero-general uses 1 canonical plane, PettingZoo 2, OpenSpiel 3 absolute; none carries a turn plane. `step()`: illegal column **raises**; learner move → win `+1` / full board `0`; else the frozen opponent is queried **on the board canonicalized to ITS perspective** → opponent win `-1` / full board `0`; else `0` and continue. **Win-before-full ordering is load-bearing** (the 42nd disc can complete a line). Randomized first player at reset. Obs arrays are freshly allocated, never views of the internal board. `truncated ≡ False`. Terminal masks are emitted **all-True**, not all-False, preserving `masking.py`'s ≥1-legal invariant — 7 all-False masks were emitted over 4000 vector steps and reached `act()` 0 times only because PPO discards `next_masks`, and the DQN path provably does consume them.

**Opponent protocol:** `select(rng) -> Opponent` (per-episode choice, so a *shared* pool object can be referenced by all N sub-envs without shared mutable state) and `move(obs, mask, rng) -> int`. `RandomOpponent`, `HeuristicOpponent` (win-in-1 / block / else uniform — its random fallback is what gives the eval set diversity, and it fires ~78% of the time regardless of learner strength), `AlphaBetaOpponent(depth)` with uniformly random tie-breaking (load-bearing: 89/100 distinct eval games with it, **2/100** without), and `AgentOpponent(snapshot)` which **samples** rather than argmaxes, with its own `torch.Generator` so a tournament matchup can be replayed in isolation.

**Learner-only trajectory collection.** The opponent's moves are env dynamics; its transitions are discarded. Both-sides collection (2×, and Connect 4 is symmetric) is valid **only** under strict mirror self-play — which is what Huang & Lee do (IEEE CoG 2019, Alg. 1: m matches → 2m trajectories, no pool) — and adopting it would forbid the pool, which is the phase's point. **No published off-policy correction exists** for the historical-opponent case in a PPO self-play loop; the 2× is genuinely forfeited. Consequence worth stating: the perspective bug where P2's observations are encoded from P1's perspective **cannot occur, because P2's trajectory is never stored** — it relocates to the three (four) sites below.

**Self-play machinery (`rl/selfplay/`).** Snapshots are `copy.deepcopy(agent)` — probe-confirmed that `agent.state_dict()` **aliases live tensors**, so a pool of state_dicts would hold references to the training weights and every "frozen" opponent would silently track the learner (the Phase-3 `log_alpha` rebind failure class). Cost 0.9 ms, ~1.03 MB each (~2/3 dead optimizer state), ~20.6 MB at `pool_size: 20` — accepted waste. `.eval()` + `requires_grad_(False)` on push (currently a no-op — zero buffers, no Dropout/BatchNorm — kept as the contract the capstone needs). **Two distinct swap boundaries**: which member plays is drawn **per episode** at reset (an opponent changing mid-game is incoherent), while new snapshots enter the pool **only at a rollout boundary**, after the `update()` that drains the buffer — so within a rollout the env is a *stochastic* env with a fixed opponent distribution, not a non-stationary one, which is what PPO actually requires. `train()` must push one snapshot **before the loop starts**: `_vector_loop`'s first statement is `envs.reset(seed=cfg.seed)`, and the push cadence guarantees the pool is empty at that moment (`IndexError` otherwise). **Strided retention** — on overflow evict the **second-oldest**, so the deque's span grows with training and covers the whole run rather than trailing it. This is the one design change the published evidence forced: Bansal et al. (ICLR 2018, arXiv:1710.03748 Table 1) is the only published ablation of pool span, and a plain 20-deep recency deque is δ≈0.8 in their parameterization — second-worst of four on Humanoid Sumo (E[Win] 0.40 vs 0.63 at δ=0.5), tied-worst on Ant, with the conclusion "training against the latest opponent leads to worst performance"; Czarnecki et al. run the exact oldest-evicted mechanism over nine OpenSpiel games including Connect Four and find cycling below a critical population size in all of them. `pool_size: 20`, `push_every_updates: 20`, `latest_prob: 0.8`. **The 80/20 split is OpenAI Five's (App. N, Table 2) and is not ablated there; the *uniform* draw over the historical 20% is ours** — they used a softmax over per-opponent quality scores (η=0.01) over an unbounded pool. AlphaStar's PFSP weighting `f_hard(x)=(1−x)^p` is the named probe lever if the flat draw wastes games on snapshots already beaten 100% of the time. **`pool_size: 1` is the naive arm** — a ≤20-update-lagged copy of itself, which is what the self-play literature means by naive — making the forgetting demonstration a **one-key config diff**; `select` must special-case size 1 (the 80/20 draw has no "rest" and raises).

**Harness changes**, all defaulting off so every existing config, run and checkpoint is untouched: `Config` gains `selfplay: dict = field(default_factory=dict)` (**not** `= {}`, which is a `ValueError` at class creation and would take down every import in the repo), `eval_win_rate: bool = False`, `checkpoint_every: int = 0`. `evaluate(..., win_rate=False)` adds `eval/win_rate` from `info["outcome"]`; a private `_run_eval_episodes()` returns `(returns, outcomes)` so `eval_returns()` keeps its exact public signature. `make_env`/`make_vec_env` gain `env_kwargs`; note `gym.make` deepcopies the *spec's* registered kwargs but not caller kwargs, so passing the pool at make time preserves identity across all 8 sub-envs while **registering it would silently give each sub-env a private pool**. `make_eval_env(cfg)` routes **four** call sites — `scripts/{eval_checkpoint,watch,record}.py` *and* `rl/train.py:137`, which would otherwise evaluate against the env's default opponent in the loop that selects `best_checkpoint`. The checkpoint ladder writes `ckpt_{step:09d}.pt` by **threshold crossing, never `step % checkpoint_every`** — `step` advances by `num_envs`, so the modulo silently yields 3 rungs instead of 9 at `num_envs` 6 or 12. Hard guard: `cfg.selfplay` together with `normalize_obs`/`normalize_reward` **raises** — they are vector wrappers and the opponent lives inside a sub-env beneath them, so the learner would act on z-scores while every snapshot acts on raw bools. `scripts/record.py` needs a ~10-line `rgb_array` renderer (`render() -> str` alone dies in `np.asarray(...)*255`), because every prior phase shipped a GIF.

**Config (`configs/connect4_{gate,random,naive,pool}.yaml`).** num_envs 8, rollout_steps 128 (batch 1024, ~12 complete episodes per env per rollout), epochs 4, minibatches 4, clip_eps 0.2, entropy_coef 0.01, value_coef 0.5, max_grad_norm 0.5, hidden_sizes [128], total_steps 2M (~188k games), eval_every 50k, **eval_episodes 400** (at 100 the se on `eval/return_mean` is 0.093, so `best_checkpoint` is a coin flip between rungs closer than ~120 Elo), checkpoint_every 200k, `eval_opponent: heuristic`, **`torch_threads: 1`** (8,473 steps/s vs 2,196 at torch's default — 3.9×). Divergences with reasons: **γ = 1.0** (with a terminal-only ±1 reward every reward is a delayed reward, so γ<1 would downweight the only signal there is — GAE §2 introduces γ explicitly as "a variance reduction parameter in an undiscounted problem", and at γ=1 the critic learns exactly P(win)−P(loss); Generals.io ships γ=1.0 on this identical reward structure and AlphaZero's value target is the undiscounted outcome); **lr anneal OFF** at 2.5e-4 — **the reason is experimental, not empirical**: no published self-play result runs a constant lr (OpenAI Five 5e-5→5e-6, Generals.io 1e-4→5e-6), but an lr decaying to 0 freezes the policy late and would suppress the very forgetting the phase exists to demonstrate; **clip 0.2** not MinAtar's 0.1 (every self-play reference uses 0.2). `best_checkpoint` feeds **no reported number** — the tournament selects.

**Solver, anchors, absolute strength (`rl/selfplay/solver.py`).** Negamax + alpha-beta, centre-first ordering, bounded transposition table, **Python-int bitboard** — measured 894k nodes/s vs a flat list's 417k and **NumPy's 351k, i.e. NumPy is the slowest option** (scalar indexing loses and there is nothing vectorizable in a negamax inner loop); `Connect4Board` keeps its array for the obs planes and the two representations cross-check each other in tests, a free extra oracle. **TT entries must carry `(value, EXACT|LOWER|UPPER)`** — fail-soft bounds stored as exact values corrupt 0.13% → 0.40% of results with the error rate **rising with depth**, and Pons validation structurally cannot see it (labels are root values; blunder rate needs child values). The validation is a **differential test against a brute-force no-pruning no-TT negamax**; Pons is external corroboration. The TT must be size-bounded (141 MB peak RSS on one Middle-Medium position). **Pons' chapter-8 iterative-deepening null-window search (~15 lines) is mandatory, not optional**: measured, alpha-beta + ordering + TT exhausts End-Easy in 0.12 s and Middle-Easy in 281 s (both 1000/1000 correct) but leaves the three Begin-* sets at 54 hours to 17 days — 3000 of 6000 positions; chapter 8 cuts Begin-Easy 660× to ~12 minutes. Six benchmark files exist, not nine, at `http://blog.gamesolver.org/data/Test_L{1,2,3}_R{1,2,3}` (**HTTPS is broken on that host** — GitHub Pages cert, wrong domain; use plain http or the `raw.githubusercontent.com/gamesolver/gamesolver.github.io/master/data/` mirror), 1000 lines each, format `<1-indexed column sequence> <score>`, score signed from the player to move with magnitude `22 − winner's stones`. Difficulty tracks **remaining** moves, not moves played; Pons' "remaining" **excludes** the final winning move. Repo license is `null`, so files are downloaded into a gitignored `data/` and **never committed**. Metrics: **value-head sign accuracy per set, over decisive positions only, plus a Brier score against P(win)** — MAE against the graded score is rejected outright (it ranks a constant-zero critic at 0.218 above a perfect γ=1 critic at 0.643, because Pons grades by moves-to-win over ±18 while the critic learns the outcome), and the draw fraction runs 0%→43% across the sets so an aggregated number silently means different things. Policy metrics (blunder rate, optimal-move agreement, score regret) over the solver-exhausted subset, **coverage always reported**; blunder rate needs only each child's sign, so a *weak* solver suffices there. Never subsample the benchmark to estimate runtime — Middle-Easy's node count has median 738, mean 207,307, max 96,290,338.

**Elo harness (`rl/selfplay/elo.py`, `scripts/tournament.py`).** Round-robin over the checkpoint ladder plus four fixed anchors (`random`, `heuristic`, `alphabeta2`, `alphabeta4`), **first player alternated exactly** N/2 each way, **both sides playing stochastically** (a published Connect 4 round-robin found "in the majority of matchups, the repeat games shared an identical move sequence" under deterministic play). **Bradley-Terry MLE by MM** (order-independent by construction), draws 0.5, ratings anchored with `alphabeta2` at 0. **No pseudo-count prior**: a Ford/Assumption-1 strong-connectivity check before every fit (Hunter 2004 Lemma 1(a) makes it necessary, not merely sufficient), perfect scorers **dropped and reported with a floor/ceiling** (Ordo's approach), and the unit test asserts rating **stability across iteration counts** (200/2k/20k) rather than finiteness — an undefeated player does not diverge to inf, it creeps at a constant ≈372 Elo per decade of iterations while the step size decays like 1/k, so a successive-difference test reads it as slow convergence and returns a finite, wrong, tolerance-dependent number. If a prior is ever wanted it is **phantom-player ρ**, named explicitly — "half a virtual win and loss per player" is ambiguous between Glickman's (arXiv:2606.03805) phantom-player and pseudo-game readings, which differ by a factor of J (=14 here); δ=0.5 corresponds to "a player who won its only game is only 75% to win the next" and compresses the ladder ~2% at 100 games/pair. **≥500 games per pair** (95% CI width 43 Elo, vs 90 Elo at 100 — and adjacent rungs of a 10-rung ladder spanning ~600 Elo sit ~65 Elo apart). **Bootstrap B = 1000, seeded, stratified by (pair, colour)** — at B=200 each endpoint carries ±2 Elo of Monte-Carlo jitter on a ~45-Elo interval and small-B percentile intervals are biased narrow; an i.i.d. bootstrap over games destroys the exact colour balance and reports sd 0.021 where the truth is 0. Hunter p. 402's trap applies directly: at B=1000 assume at least one resample violates Assumption 1, so the loop drops or flags failures and **never** returns the iterate at `max_iter`. Cycling detector = intransitive-triple fraction **against a null band** from the refitted BT matrix (acyclic ground truth yields 7.2–7.7% spurious cycles at the 40-Elo ladder spans late training produces).

**Forgetting demonstration.** Naive (`pool_size: 1`) vs pool (`pool_size: 20`), 3 seeds each, one-key diff. **Primary measure is AlphaStar's published proxy** (Nature 2019 Fig. 3C/D): `min_{j<i} winrate(ckpt_i vs ckpt_j)` averaged over i — free from the same round-robin matrix and strictly more sensitive than a pairwise fraction. Regression rate is **secondary and only against a null band**: simulated on a BT ladder with exactly zero forgetting it reads 47.8% for a run that never learns, ~13.9% for genuine forgetting and 2.1% for a fast monotone learner, so as a bare number it ranks "never learns" as the worst forgetter — and the naive arm is expected to be the weaker learner, pointing the confound straight at the desired conclusion.

**Degeneracies — what is invisible on this env.** The named one: the mask is all-True at **63.8%** of learner decision points and **single-legal-column positions are 0.53%** (~1 in 190), so the hand-written fixture is load-bearing and fuzz alone is flaky. Others found in review: the **draw branch is never exercised** by weak play (0.27% of 20k random games, 0 draws across 300 eval episodes — needs a scripted fixture plus a nonzero-draw assertion in the self-play run); `loss/value` has a floor of ~0.84 at γ=1 with ~16% draws, so a critic that learned nothing and a critic at the self-play equilibrium report the same number (pre-register 0.84); `rollout/episode_return` is pinned at ~0 under self-play, and it is the curve read first; **~31% of episode records are silently merged** (P(≥2 of 8 sub-envs finish on the same vector step) = 0.170 at 10.6 steps/episode against MinAtar's 2.8e-05 — the vector loop's "simultaneous finishes are rare" comment stops being true here) — **not fixed**, the surviving ~69% is an unbiased subsample of ~188k episodes and `eval/*` are the metrics of record, documented as chunk 4 documented Freeway's shared-step artifact; rewards are 0 on ~11 of every 12 transitions; and one RNG stream has three consumers (first-player flip, `select`, heuristic fallback) with nothing pinning the draw order.

**Probes that must exist, with the mutations that prove them.** Three (four) perspective sites: the obs handed to the learner; **the obs handed to the frozen opponent** (a wrong perspective here is symmetric and self-play cannot detect it, because both sides are the same net); the reward sign on the opponent's reply; and — found in review — **terminal `next_obs` perspective flips with who ended the game**, harmless under PPO because GAE zeroes the bootstrap at `terminated=1` but contradicting `rollout.py`'s stated invariant. Frozen-opponent probes assert the snapshot's action *distribution* is bit-identical after the learner moves, and that no snapshot parameter appears in the **learner's** optimizer (asserting against the snapshot's *own* optimizer fails — deepcopy carries it). The mask probe is `lr=0 ⇒ approx_kl == 0.0 exactly`; the valid silent mutation is `torch.ones_like(flat_masks[idx])` (dropping the mask outright *crashes*), and it is well-powered — 15.6% of rows carry an illegal column, max importance-ratio error 7.04×. Keep a standing test recording that **the same mutation is invisible under all-True masks**. Aliasing: `np.shares_memory` on obs vs the internal board, and the sharper form — `obs` and `next_obs` from one step must not be the same object. Truncation: `gym.wrappers.TimeLimit` forces the path that is dead on this env. `assert eval/return_std > 0` — the free detector for a tie-break-free anchor collapsing 100 eval episodes to 2 distinct games.

**Two forks deliberately left open, to be settled by measurement.** (1) **`gae_lambda`**: Tier-1 0.95 with **λ=1.0 as a pre-registered probe arm at the pathfinder**. The lenses agreed on the arithmetic and disagreed on the conclusion — with a terminal-only reward and an inaccurate critic `A_t ≈ (γλ)^(T−t)·r_T`, so λ=0.95 delivers only 0.610 of the outcome to the opening move of a mean-length game and 0.358 at 21 steps, versus GAE §4's "λ<1 introduces bias only when the value function is inaccurate" and Generals.io's shipped λ=0.9 at γ=1.0. Runs are ~4 minutes; this is cheaper to measure than to argue. (2) **Conv receptive field**: `ConvQNet`'s single `Conv2d(2,16,kernel_size=3)` means one unit sees a 3×3 patch while a Connect 4 win is a line of **four**. The FC layer can compose it, but this was inherited from MinAtar unexamined; `kernel_size=4` gives 26,135 params, **fewer** than the current 83,816. ## Phase 5 — capstone (decided 2026-07-25: Pokémon Showdown Gen 1)

**Env:** Pokémon Showdown Gen 1 singles, battle phase only (no teambuilding) — poke-env driving a local Node.js Showdown server, starting format `gen1randombattle`. **Hero algorithm:** the Phase 2 PPO with self-play. Legal actions change every turn (fainted Pokémon can't be switched to, moves run out of PP, forced switches), which is why the action-masking contract lives in the harness now (landed mid-Phase 2, env-agnostic, all-True default) while everything Pokémon-specific stays deferred until Phase 4 completes: no poke-env dependency, no battle logic, no Pokémon observation encoders during Phases 2–4.

**API corrections from the Phase 4 review (poke-env 0.15.0 source, 2026-07-26) — the plan named a dead API.** `Gen*EnvSinglePlayer` was **removed in 0.8.4** (2025-04-20) along with `EnvPlayer` and `OpenAIGymEnv`. The live surface is **`SinglesEnv`**: subclass, implement `calc_reward(battle)` and `embed_battle(battle)`, assign `observation_spaces`. Three further shape facts, each a bounded known cost rather than a surprise: (1) **the opponent does not live inside poke-env's env** — `PokeEnv` is a PettingZoo `ParallelEnv` with two server-connected `_EnvPlayer`s and no `opponent` parameter, and the opponent enters one level up via `SingleAgentWrapper(env, opponent)`; what transfers from Phase 4 is the learner-facing contract (`(obs, float, terminated, truncated, info)`, an opponent held as a plain policy object, a `calc_reward(state)` hook), not the opponent's *location*. (2) **poke-env puts the action mask in the OBSERVATION, not `info`** — it rewrites the obs space to `Dict({"observation", "action_mask"})`, as PettingZoo classic does; our harness contract matches Shimmy/OpenSpiel instead, so Phase 5 needs one adapter wrapper lifting `obs["action_mask"]` into `info`. (3) **`truncated` is load-bearing here where it is dead on Connect 4** — `calc_term_trunc` sets `terminated=True` only for a decisive wipe, while **forfeits, ties and timer losses all return `truncated=True`**, and `reset`/`close` inject `ForfeitBattleOrder()`. Reward shape transfers cleanly (`calc_reward(self, battle) -> float`, no sign-flip machinery — egocentricity is a property of the state handed to each seat). Vectorization does not: poke-env is one battle per env instance and scales via `SubprocVecEnv` over `SingleAgentWrapper` factories.

**Direct precedent (found 2026-07-25):** Huang & Lee, *"A Self-Play Policy Optimization Approach to Battling Pokémon"* (IEEE CoG 2019) is this exact architecture — PPO + self-play on Pokémon Showdown, actor-critic with GAE and an entropy bonus, and masked softmax over illegal actions. It reached 1677 Glicko-1 on the ladder and beat `pmariglia` (the tree-search SOTA bot) 612–388, over 3.84M self-play matches (~6 days, ~$91 on GCP). **Three corrections from the Phase 4 review, all of which weaken the original reading:** (a) they **renormalize after the softmax** (`π_i = s_i π'_i / (sᵀπ')`) where we mask *logits* with a finite sentinel — same contract, different gradient path, so "our masking contract, independently arrived at" overstates it; (b) "they needed dense reward shaping" is an **inference** — no ablation is reported, they say only "to speed up learning", and Generals.io (arXiv:2606.23348) argues shaping is a throughput artifact ("at low throughput few games finish, so the terminal signal alone is too sparse") and finds sparse reward converges *more* cleanly; (c) **their own §V-C reports catastrophic forgetting**: RL-meta, fine-tuned from RL-rb for only ~10% additional training on a narrowed opponent distribution, wins **77/500 (15.4%)** against the model it came from, in the format it was originally trained on. That is published, quantitative forgetting in this domain, and it substantially weakens "naive self-play was sufficient" — naive self-play was sufficient *to reach 1677 against ladder humans*, which is the defensible claim. Their feedforward-with-LSTM-as-future-work finding stands, so recurrence remains an option rather than a precondition.

**A stronger, more recent anchor: Metamon** (Grigsby et al., *Human-Level Competitive Pokémon via Scalable Offline RL with Transformers*, RLJ 2025, arXiv:2504.04395). SynRL-V2 reaches **Gen1OU GXE 79.9%, Glicko-1 1761 ± 35 over 613 human ladder battles**, peak global rank #31 in Gen1OU. Protocols differ from Huang & Lee's (different tier, different era, GXE vs raw Glicko) and **must not be mixed**. Two findings directly load-bearing for us: they **do not mask actions** ("if the agent selects an invalid action, it is replaced by a random valid action") and name invalid-action selection from PP stalls as "their most noticeable flaw" — direct evidence our masking contract is right; and their self-play arm overfit to its own checkpoints (§5.3, quoted in Phase 4's pre-registered expectations), fixed by deliberate opponent and team diversification.

**Milestone ladder (each independently shippable):** beat `MaxBasePowerPlayer` → beat `SimpleHeuristicsPlayer` → self-play with a historical-checkpoint opponent pool → optional: live Showdown ladder Elo.

**Headline metric:** win rate vs `SimpleHeuristicsPlayer` over ≥1000 battles, multiple seeds. Ladder Elo is an optional flourish, not the metric. Budget the eval variance off Huang & Lee's **1000 matches per matchup**, not off Phase 4's 400 — theirs is driven by team randomization, which `gen1randombattle` has and Connect 4 does not.

**Fallback if self-play stalls:** Procgen generalization study (train/test level gap) — the previous lean, kept ready.

Runs on a rented cloud GPU where compute-bound; W&B merges local + cloud runs into one dashboard.
