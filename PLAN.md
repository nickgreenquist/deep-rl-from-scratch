## Benchmark protocol (Phases 1–4)

Every headline result comes from **≥3 independent training seeds** (5+ for the capstone), reported as mean ± std across seeds — deep RL is brittle with respect to random seed (per Spinning Up), so single-run numbers don't count. The per-run eval protocol (fixed eval seeds, deterministic policy, N episodes) is unchanged.

Execution: any run longer than ~5 minutes — i.e. every real training run (a 5M-step MinAtar run is ~55 min) — is launched by the maintainer in their own terminal; Claude hands over the exact command (env vars included) and picks up from the logged output and checkpoints. Learned on a prior project: training launched through Claude Code tooling runs ~10x slower. Short smokes and tests stay in-session.

## Phase 1 — DQN (discrete track)

Replay buffer, target network, ε-greedy exploration; Double DQN / Dueling / n-step returns as config toggles. Benchmark on CartPole/LunarLander for sanity, then MinAtar (install `minatar` at phase start). Headline metric vs a published baseline.

**On-ramp (first step of the phase): linear Q-learning on CartPole.** The DQN skeleton with a zero-hidden-layer network (`nn.Linear(4, 2)`) — a linear model borrowing all the same infra. Isolates the one conceptual leap from Phase 0 (shared weights generalize across states; the same TD error now takes a gradient step instead of a table-cell nudge) and meets the deadly triad — function approximation + bootstrapping + off-policy, where tabular convergence guarantees evaporate — *before* the target network and replay buffer arrive as its stabilizers. Then add the hidden layer and it's DQN. Optional half-hour calibration first: random search over linear policies solves CartPole outright — a reminder that "solves CartPole" is a low bar, which is why the headline benchmark is MinAtar.

**Visuals (starts here, grows with the project):** better visuals serve three purposes — learning (seeing what a policy actually does), validation (a rendered rollout catches bugs metrics hide), and eventual sharing/posts (this repo is a portfolio piece). First deliverable, once DQN produces a policy worth showing: a `--record` path or `scripts/record.py` using `render_mode="rgb_array"` to save rollouts as annotated GIFs/videos (episode/step/return stamped on frames — cheap once frames are in hand) for the README and posts. Explicitly rejected: HUD overlays in the live `render_mode="human"` window (gymnasium exposes no API for it; the pygame workarounds are fragile) — `watch.py`'s terminal narration covers live viewing.

**Chunk 3 — `PPOAgent` spec (locked):**

- *Files:* `rl/agents/ppo.py` (agent + the clipped-surrogate math factored as a pure module-level function for hand-computed tests); `rl/train.py` (register `ppo` in `ALGOS`; `make_agent` passes vectorized agents `env.single_observation_space`/`single_action_space` plus `num_envs=env.num_envs`, with `getattr` fallbacks so the scalar-env rebuild in watch/record/eval_checkpoint gets plain spaces and `num_envs=1`); `rl/networks/mlp.py` (`activation` kwarg, default ReLU — existing users untouched); `configs/cartpole_ppo.yaml`; `tests/test_ppo.py`; `tests/test_harness.py` (`_VecRandomAgent` updated to the vectorized constructor contract).
- *Nets:* separate actor and critic `mlp(obs_dim, [64, 64], out)` with **Tanh** hidden activations; orthogonal init — gain √2 hidden, **0.01 policy head** (near-uniform initial policy), 1.0 value head, zero biases. One Adam over the union of both nets' params, **eps=1e-5**.
- *Update (when the rollout buffer fills):* one no-grad batched forward recomputes values, next_values (from per-row next_obs), and old_logp — exact, the policy is unchanged since collection → `compute_gae` (γ=0.99, λ=0.95); value targets = advantages + values → 4 epochs × 4 minibatches (transition-level reshuffle each epoch over the flattened T·N=1024 → 256/minibatch), per-minibatch advantage norm `(A−mean)/(std+1e-8)` → loss = clipped surrogate (ε=0.2, pessimistic min) + 0.5·MSE value loss − 0.01·entropy → **one** `clip_grad_norm_` call over the param union, max norm 0.5 → clear buffer.
- *Metrics:* `loss/policy`, `loss/value`, `loss/entropy`, `loss/approx_kl` (estimator `((ratio−1)−logratio).mean()`), `loss/clip_frac` (fraction of |ratio−1| > ε). approx_kl + clip_frac are the collapse-vs-bad-hyperparameter discriminators.
- *Contracts:* `act()` branches on obs rank (single eval obs vs batched collection — no unconditional `unsqueeze(0)`); obs AND next_obs cast to float32 at tensor time (MinAtar planes are bool); `update()` stores the batched row and returns `{}` until full. `state_dict`: actor, critic, optimizer, update counter.
- *Config (`cartpole_ppo.yaml`):* num_envs 8, rollout_steps 128, epochs 4, minibatches 4, lr 2.5e-4 constant, clip_eps 0.2, entropy_coef 0.01, value_coef 0.5, max_grad_norm 0.5, gamma 0.99, gae_lambda 0.95, hidden_sizes [64, 64], total_steps 150k (same budget as the REINFORCE run so the overlay is honest), eval_every 5000, eval_episodes 20, seed 0.
- *Deliberate omissions (document in the module docstring):* value-loss clipping (Engstrom 2020: no evidence it helps; Andrychowicz 2021: can hurt; with separate nets its one theoretical benefit can't apply) and lr annealing (deferred to the MinAtar benchmark config, where Andrychowicz says it pays). Docstring note: under disjoint-param Adam, value_coef is ~inert for the critic itself (it mostly modulates the critic's share of the shared grad clip); a persistently underfitting critic wants a second optimizer, not a bigger coef.
- *Tests:* hand-computed clipped-surrogate cases through the factored loss fn (positive advantage clips at 1+ε, negative at 1−ε, pessimistic min verified); update cadence (returns `{}` for rollout_steps−1 calls, metrics + cleared buffer on the fill); train-loop smoke.
- *Deliverables beyond code:* full `cartpole_ppo.yaml` run, history extraction, de-biased `eval_checkpoint.py` re-eval, REINFORCE-vs-PPO overlay figure from the two runs' `history.csv`.

**Chunk 4 — PPO on MinAtar spec (locked 2026-07-25):**

Goal: the discrete-track headline — DQN vs PPO apples-to-apples on all 5 MinAtar games, 3 seeds × 5M steps, harness unchanged. The config follows the 8-env Atari-CNN recipe (ppo2 `atari()` / CleanRL `ppo_atari.py`) coherently rather than mixing recipes; the MinAtar-JAX references (PureJaxRL, gymnax-blines: 64 envs, lr 5e-4–5e-3, clip 0.2, γ 0.999, flatten-MLP) form a second coherent recipe whose levers are the named probe tier if health bands fail. Locked after a three-Opus-lens review (published-evidence / reference-implementation / adversarial): 10 keep / 3 amend / 0 reject; two probe-confirmed conv crashes fixed at spec time; see session log.

- *Files:* `rl/agents/ppo.py` (rank-general act, conv net selection, flattened recompute, lr anneal); `rl/networks/conv.py` untouched — `ConvQNet` is reused as the generic conv→FC net for both PPO heads (dueling stays off, and must: with dueling the last Linear in module order is `advantage`, so the head-gain rule would mis-init `value` — probe-confirmed); `configs/minatar_<game>_ppo.yaml` × 5 (**num_envs stays a top-level config field** — under `agent:` it collides with make_agent's injected `num_envs=` kwarg → TypeError); `tests/test_ppo.py` (anneal endpoint hand-checks at update 0/mid/last; act() rank tests covering **single rank-3 obs, deterministic and stochastic**, plus batched rank-4); `tests/test_minatar.py` (PPO smoke with `num_envs: 2`, **sized to force ≥ one full rollout fill AND ≥ one eval pass** — the two conv crash paths below are invisible to a shorter smoke).
- *Nets:* separate actor and critic, each `ConvQNet(observation_space.shape, [128], out)` — the DQN trunk arch (Conv 16@3×3 → FC 128), so the DQN-vs-PPO comparison holds per-net architecture fixed; per-game channel counts (Breakout 4 … Seaquest 10) adapt automatically. **Framing (corrected in review): separate nets departs from the conv-PPO lineage** — CleanRL/ppo2/SB3 pixel PPO all share the trunk; the support for separate is PureJaxRL's separate actor/critic stacks, chunk-3 contract/checkpoint continuity, and noise-level duplicate compute at 16 filters. **ReLU, not Tanh** (unanimous across every conv reference; ConvQNet already hardcodes it — no activation kwarg needed). Init values = CleanRL `layer_init` exactly (orthogonal √2 on conv + hidden, 0.01 policy head, 1.0 value head, zero biases); **mechanics amended:** `_orthogonal_init` must iterate `net.modules()` — the landed `for m in net` raises TypeError on non-Sequential ConvQNet (probe-confirmed); last-Linear-is-head verified for both ConvQNet (non-dueling) and the MLP path.
- *Agent changes (two review-caught crashes fixed at spec time):* **(1) act():** rank detection stays (`single = obs_t.ndim == self.obs_rank`, obs_rank stored at init) but a detected-single obs is **unsqueezed to a batch of 1 before the forward** and the action indexed back out — Conv2d/Flatten require the batch dim, so the draft's branch-only generalization crashes at the first eval (step 100k) and in every watch/record/eval_checkpoint rebuild (probe: mat1/mat2 shape error; DQN's own unsqueeze comment is the precedent). Chunk-3's "no unconditional unsqueeze" is hereby restated as "branch on rank, batch the single path". **(2) update() recompute:** buffer tensors are (T, N, \*obs) — rank 5 for conv, which conv2d rejects (probe: dies on the first rollout fill); the no-grad recompute runs on (T·N)-flattened tensors and reshapes values/next_values/old_logp back to (T, N) for `compute_gae`. The draft's "buffer already MinAtar-ready" claim held for storage, not for the recompute forward. **(3) Constructor:** obs check widens to rank ∈ {1, 3}; rank 3 selects ConvQNet (no config key — DQN's rule); store `self.obs_rank` and `self.base_lr`. **(4) lr anneal** (the chunk-3 deferral, per Engstrom/Andrychowicz): `lr_anneal_steps` keyword arg **default 0 = off** (the CartPole config must construct unchanged); at each fill, before the epoch loop, write `lr_t = base_lr · max(0, 1 − steps_seen / lr_anneal_steps)` into `optimizer.param_groups[0]["lr"]` (single group over the union), with `steps_seen = updates · buffer.horizon · buffer.num_envs`. Endpoints verified: update 0 gets full lr, the last (4,882nd) gets ≈9.3e-8 — never exactly 0, no wasted update; resume-safe via the checkpointed `updates` counter; inert for eval-only restores.
- *Config (`minatar_<game>_ppo.yaml`, one set of numbers for all 5 — Tier-1 discipline):* num_envs 8, rollout_steps 128 (batch 1024), epochs 4, minibatches 4, lr 2.5e-4 with lr_anneal_steps 5_000_000, clip_eps 0.1, entropy_coef 0.01, value_coef 0.5, max_grad_norm 0.5, gamma 0.99, gae_lambda 0.95, hidden_sizes [128], total_steps 5M, eval_every 100k, eval_episodes 20 (harness numbers = the DQN campaign's; 5M and 100k divide by 8, so evals and the end land exactly; 4,882 full updates, 104 trailing transitions discarded mid-fill ≈ 0.002%). Two knobs diverge from the MinAtar-JAX refs and say so: **clip 0.1** is the Atari-recipe value (all three MinAtar-JAX refs use 0.2) — kept because it's coherent with the chosen recipe and mechanically raises clip_frac, sharpening the chunk-3 diagnostic; **γ 0.99** is the DQN-parity value (all MinAtar-JAX refs use 0.999 — the likeliest single lever behind their high scores on the unbounded games; first-named probe candidate with lr).
- *Benchmark seeds 0 / 100 / 200, not 0/1/2:* gymnasium's vector reset fans out as seed+i (verified against 1.3.0 source and by probe), so 8-wide runs at adjacent seeds would share sub-env episode-RNG streams; spacing by 100 keeps the windows disjoint with zero code change. All other seed pathways audited: spaces RNG is inert for PPO (no `action_space.sample()`), the eval ladder lives at 10_000+, model/numpy/python RNG were never shared.
- *Health-band follow-through (amended):* the clip_frac band **recalibrates to ~0.05–0.2 for clip 0.1** (0.1–0.3 was calibrated on clip-0.2 traces) and is **judged over the peak-lr first ~1M steps, not at 5M** — the anneal drives clip_frac → 0 late by construction, so an end-of-run ≈0 is uninformative. Decision rule: in band over the first 1M → the chunk-3 CartPole observation closes as "easy env + big batch"; still ≈0 there while curves climb → probe tier, **direction up**: lr 5e-4 (gymnax-blines' constant value) first, then γ 0.999 / larger batch (the MinAtar-JAX levers).
- *Comparison protocol (amended — headline restructured):* launched from a committed tree in the maintainer's terminal (throughput gate on the pathfinder run; PPO's 16 grad steps per 1024 transitions vs DQN's ~1024 projects PPO ≤ DQN's ~55 min/5M). **The cross-algorithm headline is the de-biased greedy 100-episode re-evals (final + best), which tax both algorithms identically.** Last-500k training return is demoted to per-algorithm curve context only: DQN's pays a constant ε=0.1 tax while PPO's pays a sampling tax that shrinks as entropy falls, so cross-algorithm training-return gaps are exploration-mechanism artifacts. Best-vs-final churn comparisons: PPO's late-run lr (≤ 2.5e-5 in the last 500k) mechanically compresses its gap — don't read it as stability. The MinAtar paper's curves anchor DQN only; **external PPO anchors** (directional, not budget-matched — 10M steps, 64 envs, γ 0.999, flatten-MLP): gymnax README reports Breakout 28, Freeway 58, Asterix 15, SpaceInvaders 131; **Seaquest has no published PPO anchor** (gymnax doesn't register it) and stays internal-only. Sanity read: PPO landing well below DQN on Breakout or SpaceInvaders is a bug signal, not a finding.
- *Known logging artifact (review-found):* Freeway is a fixed 2501-step frame timer (probe: every seed/action), so all 8 lockstep sub-envs finish simultaneously forever and each episode's 8 returns log at one shared W&B step — the vector loop's "simultaneous finishes are rare" caveat is systematic there. The headline is unaffected (re-evals); before trusting Freeway training-return curves, check on the first Freeway run whether same-step rows survive `extract_history.py` (the UI merges; the datastore may keep all rows) and document which.
- *Campaign monitoring (review-found):* training has no episode cap (the Phase-1 10k cap is eval-only) — collection is horizon-bounded so nothing hangs, but a sub-env that learns Seaquest's immortal oxygen loop stops logging episodes and ramps difficulty off-distribution. Watch Seaquest ep_length / episode-log density over the last 500k. A training-side cap is rejected: it would break reward-stream parity with the uncapped DQN runs.
- *Deliberate non-goals (rationales corrected in review):* no shared trunk (above); no observation normalization (binary 0/1 planes; the 37-details obs-norm item targets unbounded continuous obs); no reward clipping (sign-clipping is a no-op on MinAtar's 0/1 rewards) and **no reward/return normalization** — the one omitted knob with positive ablation evidence (Engstrom 2020: significant for PPO) — scoped out for reward-stream parity with DQN and documented as the probe-tier candidate if PPO underperforms broadly; no value-loss clipping — resting on the ablation evidence (Engstrom 2020 no-help, Andrychowicz 2021 no-sig-diff), **not** on the separate-nets argument (PureJaxRL ships value clipping with separate nets — live counterexample); no per-game hyperparameters at Tier 1 (probes are the diagnostic tier, as in Phase 1).
- *Sequencing:* (a) implement, tests green; (b) single-seed Breakout pathfinder run in the maintainer's terminal — all four health bands (clip_frac per the recalibrated rule) + throughput, before scaling; note the pathfinder cannot surface the Seaquest immortal-sub-env risk (Breakout always terminates) — that's what the campaign-monitoring bullet is for; (c) 15-run campaign; (d) README Phase 2 results section (CartPole overlay + MinAtar table/figure land together).

## Phase 3 — SAC (continuous track)

## Phase 4 — capstone (decided 2026-07-25: Pokémon Showdown Gen 1)

**Env:** Pokémon Showdown Gen 1 singles, battle phase only (no teambuilding) — poke-env driving a local Node.js Showdown server, starting format `gen1randombattle`. **Hero algorithm:** the Phase 2 PPO with self-play. Legal actions change every turn (fainted Pokémon can't be switched to, moves run out of PP, forced switches), which is why the action-masking contract lives in the harness now (landed mid-Phase 2, env-agnostic, all-True default) while everything Pokémon-specific stays deferred until Phase 3 completes: no poke-env dependency, no battle logic, no Pokémon observation encoders during Phases 2–3.

**Milestone ladder (each independently shippable):** beat `MaxBasePowerPlayer` → beat `SimpleHeuristicsPlayer` → self-play with a historical-checkpoint opponent pool → optional: live Showdown ladder Elo.

**Headline metric:** win rate vs `SimpleHeuristicsPlayer` over ≥1000 battles, multiple seeds. Ladder Elo is an optional flourish, not the metric.

**Fallback if self-play stalls:** Procgen generalization study (train/test level gap) — the previous lean, kept ready.

Runs on a rented cloud GPU where compute-bound; W&B merges local + cloud runs into one dashboard.
