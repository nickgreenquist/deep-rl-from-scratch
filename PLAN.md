## Benchmark protocol (Phases 1–4)

Every headline result comes from **≥3 independent training seeds** (5+ for the capstone), reported as mean ± std across seeds — deep RL is brittle with respect to random seed (per Spinning Up), so single-run numbers don't count. The per-run eval protocol (fixed eval seeds, deterministic policy, N episodes) is unchanged.

Execution: any run longer than ~5 minutes — i.e. every real training run (a 5M-step MinAtar run is ~55 min) — is launched by the maintainer in their own terminal; Claude hands over the exact command (env vars included) and picks up from the logged output and checkpoints. Learned on a prior project: training launched through Claude Code tooling runs ~10x slower. Short smokes and tests stay in-session.

## Phase 1 — DQN (discrete track)

Replay buffer, target network, ε-greedy exploration; Double DQN / Dueling / n-step returns as config toggles. Benchmark on CartPole/LunarLander for sanity, then MinAtar (install `minatar` at phase start). Headline metric vs a published baseline.

**Known, chosen difference from common DQN references (audited 2026-07-25 against the PyTorch DQN tutorial): our DQN applies no gradient clipping.** PPO clips grad-norm at 0.5; DQN clips nothing, where that tutorial uses `clip_grad_value_(params, 100)`. Largely self-mitigating — the Huber loss already clamps ∂L/∂Q to ±1 per sample, which is the dominant gradient-blowup path in DQN and much of why Huber is the standard choice there; a value clip at 100 is a loose outer safety net on top. **Deliberately not added**: no instability appeared across 63 five-million-step runs, and changing it now would break comparability with the entire Phase 1 campaign for no measured benefit. Other differences from that tutorial are all MinAtar-paper fidelity rather than oversight — hard target sync every 1000 gradient steps (not Polyak τ=0.005), linear ε decay (not exponential), Adam/centered-RMSprop (not AdamW+amsgrad), batch 32 / buffer 100k / lr 2.5e-4 — and the optimizer question was settled empirically in Phase 1 rather than by default-copying. Terminal handling is equivalent to the reference (`(1 - terminated)` masking vs their `next_state = None`), and both bootstrap correctly through truncation.

**On-ramp (first step of the phase): linear Q-learning on CartPole.** The DQN skeleton with a zero-hidden-layer network (`nn.Linear(4, 2)`) — a linear model borrowing all the same infra. Isolates the one conceptual leap from Phase 0 (shared weights generalize across states; the same TD error now takes a gradient step instead of a table-cell nudge) and meets the deadly triad — function approximation + bootstrapping + off-policy, where tabular convergence guarantees evaporate — *before* the target network and replay buffer arrive as its stabilizers. Then add the hidden layer and it's DQN. Optional half-hour calibration first: random search over linear policies solves CartPole outright — a reminder that "solves CartPole" is a low bar, which is why the headline benchmark is MinAtar.

**Visuals (starts here, grows with the project):** better visuals serve three purposes — learning (seeing what a policy actually does), validation (a rendered rollout catches bugs metrics hide), and eventual sharing/posts (this repo is a portfolio piece). First deliverable, once DQN produces a policy worth showing: a `--record` path or `scripts/record.py` using `render_mode="rgb_array"` to save rollouts as annotated GIFs/videos (episode/step/return stamped on frames — cheap once frames are in hand) for the README and posts. Explicitly rejected: HUD overlays in the live `render_mode="human"` window (gymnasium exposes no API for it; the pygame workarounds are fragile) — `watch.py`'s terminal narration covers live viewing.

**Discrete PPO audited against the TorchRL PPO tutorial (official PyTorch docs), 2026-07-25 — three divergences, all on the canonical side; no changes made.** (1) *Advantage recomputation*: the tutorial recomputes GAE inside the epoch loop ("its value depends on the value network which is updated in the inner loop"); we compute it once per rollout. Ours is correct for PPO — the objective is defined over `A^{π_old}`, the importance ratio corrects for policy drift and not critic drift, so refreshing V mid-epochs does not improve the estimate of `A^{π_old}`, it only makes the target move during optimization; baselines/ppo2, CleanRL and SB3 all compute once. Note what we *do* recompute is a different thing and stays: `values`/`old_logp` are recomputed once **at update start** rather than stored during collection (exact — the policy hasn't changed since it acted). (2) *Critic loss*: we use MSE, the tutorial defaults to `smooth_l1`; canonical PPO is MSE. The asymmetry with our DQN (Huber) is deliberate — DQN's TD targets are genuinely outlier-prone, PPO's are GAE returns. (3) *Advantage normalization*: ours is per-minibatch (CleanRL/SB3), the tutorial's `average_gae=True` normalizes the whole batch.

**Continuous track — pre-spec decisions (drafted 2026-07-25; resolved into the chunk-5 spec below by its three-lens review, 2026-07-26).** The TorchRL tutorial is a valuable reference precisely because it takes the *non*-canonical side on three of four forks, which makes the forks visible. Each of these is cheap to decide now and expensive to discover after a benchmark campaign — the chunk-4 lesson:

| Decision | TorchRL tutorial | Canonical PPO (CleanRL `ppo_continuous_action`, SB3, 37-details) | Lean |
|---|---|---|---|
| Action distribution | `TanhNormal`, squashed to the action spec | unbounded `Normal`, action clipped to bounds, log-prob of the **unclipped** action | canonical |
| Scale parameterization | state-dependent head + softplus | **state-independent free `log_std` parameter** | canonical |
| Observation normalization | fixed stats from 1000 random steps | **running** normalizer updated throughout training | canonical |
| Reward/return normalization | none | running return normalization (Engstrom et al. found it significant) | canonical |

- The **`log_std` fork matters most**: a state-dependent scale head is what *SAC* does (and there it needs the tanh log-det-Jacobian correction). If PPO also used one, the Phase 3 PPO-vs-SAC comparison would differ in more than the intended way — the same "hold everything fixed but the algorithm" discipline that made the discrete headline clean.
- **Fixed observation stats are a locomotion trap**: a random policy on HalfCheetah visits a completely different state distribution than a trained one, so stats computed from random rollouts go stale exactly as the agent improves.
- Both normalizers are **new harness surface**, not agent-internal: they are env wrappers with state that must be checkpointed and restored, or eval and any resumed run silently use the wrong statistics.
- **Entropy coefficient wants revisiting, not porting**: CleanRL runs `ent_coef=0.0` on MuJoCo against our 0.01 for discrete (the tutorial uses 1e-4). Exploration comes from the learned scale parameter, so the bonus carries much less weight.
- Sanity gate before any MuJoCo campaign: a cheap continuous env (Pendulum, or HalfCheetah at short budget) green first — the chunk-3 CartPole role for this track.

## Phase 3 — SAC (continuous track)

Twin Q critics, reparameterized squashed-Gaussian actor with the tanh log-det-Jacobian correction, auto-tuned entropy temperature, soft target updates. Benchmarked against the Phase 2 PPO runs on HalfCheetah-v5 / Hopper-v5 / Walker2d-v5, 1M steps × 3 seeds (0/100/200).

**Prerequisite the repo does not yet have: a shared Polyak soft-update helper** (`rl/common/`, `theta_target <- tau * theta + (1 - tau) * theta_target`, tau ~5e-3). Nothing in `rl/` implements it today — DQN hard-syncs its target net by `load_state_dict` every N gradient steps, which is the right choice there and paper-faithful, but soft updates are *core* to SAC rather than optional, and its twin critics both need them every step. It belongs in `rl/common/` as a small tested utility rather than reinvented inside the SAC agent, since that also keeps a soft-update DQN available as a cheap future ablation against the hard-sync baseline. (Surfaced 2026-07-25 while auditing our DQN against the PyTorch DQN tutorial, which uses Polyak at tau=0.005 where we hard-sync — see the Phase 1 note.)

**Phase 3 spec (locked 2026-07-26 after its three-lens review: 19 keep / 24 amend / 2 reject).** Both rejects were errors in the draft's *justifications*, not its choices — every design decision survived. Recipe taken WHOLE: CleanRL `sac_continuous_action.py` (the chunk-4 lesson; mixing coherent recipes is how MinAtar got mis-tuned).

**Three forks the maintainer settled before the review, and must not be silently re-litigated:**

- **M1 — SAC runs on RAW envs**, no obs/reward normalization, where our PPO's MuJoCo configs run with both on. Every SAC reference (paper, SpinningUp, CleanRL, SB3 default, Tianshou) runs raw, so published SAC numbers stay valid anchors — and for a from-scratch implementation, off-recipe makes "a bug" and "a config difference" indistinguishable. Two independent published benchmark suites already ship *exactly* this asymmetry: Tianshou's `mujoco_ppo.py` sets `obs_norm=True`/`return_scaling=True` while `mujoco_sac.py` sets `obs_norm=False`; SB3's rl-zoo MuJoCo SAC entries carry no `normalize` key. **The confound is closed by measurement, not prose: a PPO-raw control campaign** (the shipped PPO configs with both flags false, 9 runs, ~5 min) makes the headline SAC-raw vs PPO-raw on an identical stack, with PPO-normalized reported alongside to price the env stack. The correctness case is also published — SimBa (arXiv:2410.09754 §7.1) measures env-wrapper running normalization under a replay buffer and finds it "introduces inconsistencies in off-policy settings by normalizing samples with different statistics based on their collection time"; and reward scale is not neutral for SAC specifically, because v2's auto-tuned α absorbs reward scale only against a target entropy **fixed in nats** (`H_target = −act_dim`), so a drifting reward scale makes α chase (Haarnoja 2018a: "reward scale ... the only hyperparameter that requires tuning"; 2018b §5: "the scaling factor has to be compensated by the choice of a suitable temperature").
- **M2 — Tier-1 nets 256×256 ReLU** (the paper's own Table-1 values), plus an **architecture ablation of PPO's architecture WHOLE — 64×64 Tanh — on HalfCheetah at 3 seeds**. Three seeds, not one: single-seed MuJoCo results are noise and ≥3 seeds is the repo floor everywhere else; runs are single-threaded, so 3 concurrent ≈ 1 in wall-clock. Deliberately not decomposed into a width × activation 2×2 — the question is "would matching PPO's architecture have changed the conclusion", not "what does width contribute vs activation". **Limitation stated in the write-up: one env, so the finding is "on HalfCheetah, architecture accounts for X of the gap", never a general claim.** Pre-registered against a bug hunt: the closest published predictor (Henderson et al. 2017, HalfCheetah/DDPG) has 64×64 **tanh** at 5325 ± 281 *beating* 64×64 ReLU at 4198 ± 606 and within ~5% of 400×300 ReLU, while SimBa finds actor scaling "tends to reduce performance" — **a small gap is the published-consistent outcome, not a misconfigured ablation.**
- **M3 — validate SAC against published SAC benchmarks BEFORE the PPO comparison is treated as meaningful.** That is the correctness check the take-the-recipe-whole discipline exists to buy.

**Spec:**

- *Files.* New: `rl/common/polyak.py`; `rl/agents/sac.py`; `tests/test_polyak.py`, `tests/test_sac.py`, **`tests/test_replay.py`** (review-found gap: `RolloutBuffer` has 7 direct tests, `ReplayBuffer` has **zero** — SAC's data path would land with no direct coverage); `configs/pendulum_sac.yaml`, `configs/{halfcheetah,hopper,walker2d}_sac.yaml`, `configs/halfcheetah_sac_mlp64.yaml`, `configs/{halfcheetah,hopper,walker2d}_ppo_raw.yaml`; `scripts/make_sac_figure.py`. - *Polyak (`rl/common/polyak.py`).* `polyak_update(source, target, tau)`: `for p, tp in zip(source.parameters(), target.parameters(), strict=True): tp.mul_(1 - tau).add_(p, alpha=tau)` under `no_grad`. Algebraically identical to CleanRL's `copy_(tau*p + (1-tau)*tp)` and structurally identical to SB3's `common/utils.py` helper, `strict=True` included. **Parameters only, not buffers** — probe-confirmed that every net in this repo (`mlp`, `DuelingMLP`, `ConvQNet` ±dueling) has zero buffers, and the actor's two (`action_scale`/`action_bias`) are not on the Polyak path. Rationale corrected in review: `strict=True` does **not** prevent a half-updated target (it raises *after* the leading params are already mutated in place, probe-confirmed) and in the realistic mismatched-`hidden_sizes` case a shape `RuntimeError` fires first — it bites only when shapes match but counts differ. `requires_grad_(False)` on the target is load-bearing, not decorative: without it *and* without `no_grad`, the in-place write raises.
- *Buffer.* `ReplayBuffer.__init__` mirrors `RolloutBuffer`'s chunk-5 signature: `(capacity, obs_shape, obs_dtype=float32, action_shape=(), action_dtype=int64, n_actions=None)`. Masks allocated only when `n_actions` is given, `add()` skips the write, `sample()` returns `None` in those slots — `masks is None` means "Box", fixed at construction, never a runtime branch. `discounts` stays; SAC is 1-step and writes `gamma`. **`obs_dtype=np.float32` explicitly, not the space dtype**: MuJoCo obs are float64, the net casts to float32 anyway (probe: bitwise identical), and float64 storage costs +136 MB/run for nothing — this *inverts* DQN's take-the-env-dtype rule while keeping its principle (store the narrowest dtype the net can consume), and **CleanRL does the identical cast** (`envs.single_observation_space.dtype = np.float32`). Correction: the draft's "an n-step SAC toggle stays one line away" is **false** — SAC's `add` drops `truncated`, which `NStepAccumulator` needs to cut the window; it is a signature plus plumbing change. Don't write the claim down.
- *Actor.* `mlp(obs_dim, hidden_sizes, 2*act_dim, activation)` chunked into `(mean, log_std)`. The single-head-chunk equivalence was challenged and **verified rigorously**: identical param count (3084 vs 3084), identical `fan_in` (`_calculate_fan_in_and_fan_out` reads `size(1)`, so it is independent of `out_features`), identical per-element init bound (0.0625), KS tests on weights and biases agree (p = 0.72 / 0.47), gradients through `chunk` match separate heads exactly. Two qualifications: the equivalence is *distributional*, not per-seed (RNG draw order differs, so this is not bit-reproducible against CleanRL), and it holds **only because `mlp()` applies no activation after the output layer** — if that ever changes, `chunk` silently becomes two heads sharing a nonlinearity. `log_std` uses CleanRL's tanh-rescale `LOG_STD_MIN + 0.5*(LOG_STD_MAX - LOG_STD_MIN)*(tanh(log_std) + 1)` with **(−5, 2)**, verified verbatim; SpinningUp *and* SB3 both hard-`clamp` at (−20, 2), so CleanRL is the outlier in both form and floor, and our gradient-flow rationale is sound reasoning but unsourced — say so. **No orthogonal init** (verified absent in CleanRL, SpinningUp and SB3 SAC; SB3 applies it only in the on-policy `ActorCriticPolicy`) — a stated recipe asymmetry with our PPO, not an oversight. `activation` is a config string (`relu`|`tanh`) mapped through a two-entry dict, existing solely for M2's ablation arm.
- *Log-prob.* `log π(a) = Σ_i [log N(u_i; μ_i, σ_i) − log s_i − 2(log 2 − u_i − softplus(−2u_i))]`, reduced `.sum(-1)` to `(B,)`, **never `(B,B)`**. Stable form is a **deliberate divergence from CleanRL's `log(scale·(1−y²) + 1e-6)`**, and the review found a much stronger justification than the draft's: the binding error is the **epsilon, not float32** — it distorts from |u| ≳ 7.6 in float64 too, and it drives the correction's **gradient to exactly zero in saturation** (measured `d/du`: true 2·tanh(u) → 2.0; CleanRL's form → 0.646 at u=8, **0.0** at u=9), i.e. the entropy pressure that stops the policy going deterministic switches off precisely when it is needed. Value cap `−log(1e-6) = 13.8155`/dim confirmed; float32 `1−tanh²` hits exactly 0.0 at **|u| ≥ 8.664** (draft said ">~9"), with only ~12 valid bits left by u=7. Cost recorded: the M3 anchors were produced *with* the epsilon form, so ours is no longer a bit-identical recipe. **Correction to the draft's evidence:** SB3 does **not** include the `−Σ log s` scale term (it rescales outside, in a normalized [-1,1] action space, exactly like SpinningUp), and neither does the paper (Appendix C Eq. 26). CleanRL is the *only* reference that includes it; we include it because it is correct for general Box bounds. Log it as a divergence-from-the-majority, not as majority practice. Pathfinder should log `max|mu|` to settle whether a converged actor actually reaches the saturated regime — currently asserted, not evidenced.
- *Update (per env step, CleanRL's structure).* Critic: `y = r + γ(1−terminated)·(min(Q̄1,Q̄2) − α·logπ')`, loss `mse(Q1,y) + mse(Q2,y)`. **Every Q output takes `.squeeze(-1)` and the spec must assert `y.shape == (B,)`** — the review's sharpest catch: without it `(B,1)` broadcasts against `(B,)` into a `(B,B)` target, `F.mse_loss` accepts it with only a `UserWarning`, every critic output is regressed to the **batch mean** (gradient correlation −0.82 with the correct one), and the *actor* loss is accidentally exact under the same broadcast (mean of an outer difference = difference of means) so the policy still moves and nothing looks wrong. Proven end-to-end on Pendulum, 25k steps: **−97.6 correct vs −1720.2 broadcast**, i.e. it fails §gate. A `B=1` unit test passes it. Actor+α delayed TD3-style: `if grad_steps % policy_frequency == 0: for _ in range(policy_frequency)`, **reusing the same minibatch** (verified in source; **not** the paper's scheme — Haarnoja 2018b Algorithm 1 does one actor step per env step on a fresh minibatch, and CleanRL's is an unablated TD3/Yarats import that matches the paper's *count* but batches two consecutive steps on one correlated batch). Then Polyak both critics. **Statement order is load-bearing and needs a pinning comment plus a test**: `actor_loss.backward()` differentiates through the critics and accumulates into their `.grad` (measured: critic grad-norm 0.4316 → 0.4094 after the actor step); it is safe only because the critic steps first and `q_opt.zero_grad()` precedes its backward. α must be `.detach()`ed in the actor loss (CleanRL gets this free via `.item()`).
- *Temperature.* `alpha_loss = (−log_alpha.exp() · (logπ.detach() + target_entropy)).mean()` — CleanRL's form, verified; SB3's is linear in `log_alpha` instead, with gradient ratio exactly α, same sign and same fixed point. `target_entropy = −act_dim`, derived not configured (paper Table 1 verbatim: "entropy target: −dim(𝒜)"; unablated convention, not an evidenced optimum). **`alpha_opt = Adam([log_alpha], lr=q_lr)` — the draft omitted this entirely, and the natural guess is wrong**: CleanRL runs the temperature optimizer at `q_lr` (1e-3), not `policy_lr` (3e-4), and 3.3× off there is the one loop that sets the entropy/reward exchange rate for the whole run (probe: 20k steps at constant gradient, α ≈ 2.4e19 at 1e-3 vs 2.6e3 at 3e-4). `log_alpha` init 0 → α starts at 1.0. `load_state_dict` must `log_alpha.data.copy_()`, never rebind — probe-confirmed the optimizer otherwise keeps training a phantom tensor while `agent.log_alpha` is frozen forever; **and the test must round-trip through `torch.save`/`load`, because an in-memory `load_state_dict(state_dict())` passes despite the bug** (the vacuous-test failure mode this repo has already been bitten by once). Latent, not campaign-affecting: `train()` never calls `load_state_dict`, and the three restore scripts only read `act(deterministic=True)`.
- *`act()`.* Adds/strips the batch dim itself (DQN's `unsqueeze(0)` pattern — the draft never said where the batch dim comes from, and the critic's `cat([obs, act], -1)` needs rank 2); returns `(act_dim,)` float32. Warm-up: `action_space.sample()` while `transitions < learning_starts` unless `deterministic`, so exploration lives in `act()` and the train loop is untouched (DQN's pattern). This re-activates the **space RNG** that chunk 4 recorded as inert for PPO; seeded by `make_env`'s `action_space.seed(seed)` (probe: finite, in-range and seed-reproducible on all four envs). Rationale for `make_env`'s bounds-restore **corrected — it is not about ±inf**: `Box.sample()` on an unbounded dim draws **N(0,1)**, finite but with 31.7% of components outside [-1,1], so without the restore the buffer would store warm-up actions the tanh policy can never produce and the critic would train on out-of-support actions. `deterministic=True` → `tanh(μ)·scale + bias`, bypassing warm-up; docstring precision: that is the image of the *pre-squash Gaussian's mode*, not the mode of the squashed density (the Jacobian reweights) nor its mean (no closed form). `ClipAction` is a genuine no-op (probe: `tanh(±inf)·scale + bias` lands exactly on the float32 bounds even for asymmetric ranges), left in place so the env stack is literally PPO's.

## Phase 4 — self-play on-ramp: Connect 4 (added 2026-07-25)

Goal: build and validate the self-play machinery in isolation, on an environment where a run takes minutes and a ground-truth oracle exists, before the Pokémon domain adds partial observability, stochasticity, long horizons and an external Node server on top of it. Same on-ramp discipline as linear-Q before DQN and REINFORCE before PPO: meet one new mechanism at a time. Self-play is the single genuinely new *mechanism* in the capstone; everything else there is domain.

**Hard constraint — PPO only, no MCTS.** The literature's default for Connect 4 is AlphaZero, and following it would build MCTS, search-derived policy targets and Dirichlet root noise, **none of which transfers**: tree search needs a forward model, and Showdown gives us none (Huang & Lee chose policy optimization for exactly this reason — see Phase 5). Built with our existing PPO instead, the only new pieces are the three the capstone needs and we lack. **A mediocre Connect 4 agent is a success.** The deliverable is the self-play loop and the Elo harness, not playing strength — write this down, because otherwise a weak agent reads as a bug and we repeat the chunk-4 afternoon spent proving a mis-tuned lr wasn't one.

**Env: from scratch, no new dependency.** ~36 lines of NumPy for board/legal-mask/drop/win-check plus a gymnasium `Env` shell. It emits `info["action_mask"]` natively and plugs into `make_env`/`make_vec_env` unchanged. `pettingzoo.classic.connect_four_v3` and `pyspiel.load_game("connect_four")` are used **only as differential-test oracles in `tests/`** to prove our board logic matches a reference. (PettingZoo would cost a dependency, an AEC→gymnasium wrapper of comparable size, and we'd still write opponent injection ourselves; its reference glue also returns the next agent's observation with the previous agent's reward.)

**First real workout for the masking contract.** Every env in the repo so far — CartPole, LunarLander, FrozenLake, all five MinAtar games — produces only all-True masks; the sole varying-mask exercise is the synthetic `tests/envs/masked_dummy.py`. Connect 4's full-column illegality is intrinsic and varying, so this validates infrastructure already paid for.

- [ ] NumPy Connect 4 + gymnasium `Env` with an `opponent_policy` slot inside the wrapper (learner-centric single-agent view: `step()` applies the learner's move, queries the frozen opponent internally, returns the next learner-turn state with sign-corrected reward — **this is the highest-value artifact, because it is exactly the shape poke-env forces**). Terminal ±1, randomized first player.
- [ ] Differential test against a reference implementation (board logic, legal masks, terminal detection)
- [ ] Naive self-play (opponent = frozen snapshot of the current policy). Verify: checkpoint Elo rises, win rate vs random → ~100%
- [ ] Round-robin checkpoint tournament + Elo harness, **plus a fixed external anchor** (depth-2 alpha-beta, ~30 lines) — Elo among checkpoints is purely relative, so without an anchor a whole league can drift downward and still look monotone. Tournament-matrix order-inconsistency is the cycling detector.
- [ ] Frozen-checkpoint pool (bounded deque, 80/20 latest/historical per OpenAI Five). **Demonstrate catastrophic forgetting under naive self-play first, then fix it with the pool** — the demonstration is the portfolio artifact, not the clean curve.
- [ ] Absolute strength via Pascal Pons' 6000-position labelled benchmark set: blunder rate (fraction of moves changing the position's game-theoretic value), optimal-move agreement, score regret. **No solver build required.** Note win rate vs perfect play is a degenerate metric — Connect 4 is a first-player win, so an agent scores exactly 0% as P2 forever regardless of skill.
- [ ] `eval/win_rate` added to the locked metric names in CLAUDE.md (the capstone needs it regardless)

**What this deliberately does NOT de-risk** (budget separately): the async multi-battle collection layer — our `SyncVectorEnv` of N in-process copies does not map onto poke-env's asyncio-over-websockets to a single Node server, and that is the largest remaining capstone piece; long horizons (≤42 plies vs Gen 1's >100 turns, so γ/λ/rollout length all need re-tuning); partial observability; reward shaping; and eval-variance budgeting (Huang & Lee needed 1000 matches per matchup). Connect 4 is also near-transitive, so the cycling detector gets *built* but not *validated*.

## Phase 5 — capstone (decided 2026-07-25: Pokémon Showdown Gen 1)

**Env:** Pokémon Showdown Gen 1 singles, battle phase only (no teambuilding) — poke-env driving a local Node.js Showdown server, starting format `gen1randombattle`. **Hero algorithm:** the Phase 2 PPO with self-play. Legal actions change every turn (fainted Pokémon can't be switched to, moves run out of PP, forced switches), which is why the action-masking contract lives in the harness now (landed mid-Phase 2, env-agnostic, all-True default) while everything Pokémon-specific stays deferred until Phase 4 completes: no poke-env dependency, no battle logic, no Pokémon observation encoders during Phases 2–4.

**Direct precedent (found 2026-07-25):** Huang & Lee, *"A Self-Play Policy Optimization Approach to Battling Pokémon"* (IEEE CoG 2019) is this exact architecture — PPO + self-play on Pokémon Showdown, actor-critic with GAE and an entropy bonus, and **masked-and-renormalized softmax over illegal actions** (our masking contract, independently arrived at). It reached 1677 Glicko-1 on the ladder and beat `pmariglia` (the tree-search SOTA bot) 612–388, over 3.84M self-play matches (~6 days, ~$91 on GCP). Three things this settles: PPO + self-play here is validated rather than speculative; **naive self-play was sufficient** for that result (current policy as both players, no opponent pool) so the pool is an escalation, not a prerequisite; and their agent was **feedforward, with LSTM only flagged as future work** — which answers the partial-observability question with evidence, so recurrence is an option to reach for if needed, not a precondition. Their stated reason for policy optimization over tree search — it "does not require the implementation of a simulator" — is also the argument that fixes Phase 4's no-MCTS constraint. Warning taken from them too: they needed **dense reward shaping** (−0.0125 per own faint, +0.0025 per super-effective move) on top of the terminal win/loss.

**Milestone ladder (each independently shippable):** beat `MaxBasePowerPlayer` → beat `SimpleHeuristicsPlayer` → self-play with a historical-checkpoint opponent pool → optional: live Showdown ladder Elo.

**Headline metric:** win rate vs `SimpleHeuristicsPlayer` over ≥1000 battles, multiple seeds. Ladder Elo is an optional flourish, not the metric.

**Fallback if self-play stalls:** Procgen generalization study (train/test level gap) — the previous lean, kept ready.

Runs on a rented cloud GPU where compute-bound; W&B merges local + cloud runs into one dashboard.
